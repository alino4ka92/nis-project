Развёрнут стенд ClickHouse, подготовлены материалы ClickBench, общий датасет и Docker-образ запуска бенчмарка. Датасет получен отбором по хешу из всех 100 исходных файлов. Проверена загрузка данных, проведены пробные запуски бенчмарка.

Дополнительно проверены сбор пяти метрик и обработка повторов. Подготовлены постановка исследования, конфигурации основной пары и контрольных комбинаций, восемь SQL-запросов и протокол сравнения. Параметры нагрузки сверены с сохранёнными ответами; новые измерения вариантов ещё не проводились.

[Запросы и полученные ответы](../../artifacts/checkpoint-1/docker-image-smoke.md) сохранены. Команды находятся в [инструкции запуска](../technical-checks.md#2-запуск-clickhouse).

Для коммита [`2da63c1b42ca`](https://github.com/ClickHouse/ClickHouse/commit/2da63c1b42ca1b31e42fae8837c6508a0eb07cff), указанного в карточке, доступна CI-сборка `26.9.1.552`, но официальный Docker-тег этой версии не опубликован. Для её запуска пришлось бы подготовить собственный образ из CI-бинарника. Поэтому для общего стенда выбран готовый официальный релиз `26.9.27.3`, опубликованный для ARM64 и x86-64. Материалы ClickBench использованы с закреплённой ревизии.

Для эксперимента подготовлены схема таблицы и запросы ClickBench. Это отражено в [материалах ClickBench](../../third_party/clickbench/ORIGIN.md) и [source-materials.json](../../artifacts/checkpoint-1/source-materials.json).

### Данные и проверочный пример

Из всех 100 исходных Parquet-файлов ClickBench подготовлен датасет с отбором по условию `xxHash64(toString(toUInt64(WatchID))) % 100 = 0`. Выбранные строки объединены в общий Parquet с сохранением всех колонок. Этот датасет будет использоваться в дальнейших запусках бенчмарка.

Отбор по хешу `WatchID` был использован, так как даёт воспроизводимую псевдослучайную выборку отдельных событий. При этом ожидается, что доли значений в колонках останутся близки к долям в полном исходном наборе, то есть распределения данных сохранятся приблизительно.

Источники, правило отбора и контрольные суммы записаны в [манифесте](../../artifacts/checkpoint-1/clickbench-sample.json). Данные загружены в `nis_smoke.hits` по [исходной схеме ClickBench](../../third_party/clickbench/clickhouse/create.sql).

Для проверки загрузки ответ SQL-запроса в ClickHouse сопоставлен с независимым расчётом по Parquet-файлу в Python. Проверены количество отфильтрованных строк и сумма значений одной колонки; ответы совпали. Точные значения приведены в [ожидаемом ответе](../../artifacts/checkpoint-1/clickbench-reference.json) и [результатах проверки](../../artifacts/checkpoint-1/clickbench-check.json). Команды находятся в [инструкции подготовки и загрузки](../technical-checks.md#4-подготовка-уменьшенного-clickbench).

### Пробный запуск ClickBench в Docker

Docker выбран для общего Linux-окружения на компьютерах участников: [авторский сценарий ClickBench](../../third_party/clickbench/README.md) рассчитан на Linux, а контейнер позволяет использовать одну версию клиента и один скрипт запуска на разных ОС (Linux, macOS).

Образ `nis-clickbench-benchmark` собран по [Dockerfile](../../docker/checkpoint-1/benchmark.Dockerfile) на основе официального `clickhouse/clickhouse-server:26.9.27.3`, из которого используется клиент ClickHouse. При старте контейнера скрипт подключается к уже работающему серверу ClickHouse, выполняет скрипт ClickBench и сохраняет результаты бенчмарка.

На подготовленном датасете проведены пробные запуски бенчмарка ClickBench. Запросы выполнились без ошибок.

Результаты запусков сохранены в [материалах прогона](../../artifacts/checkpoint-1/benchmark/README.md). Команды сборки и повторного запуска находятся в [инструкции Docker](../../docker/checkpoint-1/README.md#пробный-запуск-clickbench).

### Проверка метрик

На x86-64 повторена подготовка выборки, SHA-256 совпал с зафиксированным. Проверочный запрос для `CounterID = 251755` во всех выполнениях вернул ожидаемые `matched_rows = 1004`, `width_sum = 1522846`.

Ожидались один прогрев, три измеряемых повтора и все пять метрик. Это подтверждено [результатами проверки](../../artifacts/checkpoint-1/metrics/README.md). `EXPLAIN` выбрал 2 из 124 гранул; прочитано 16 384 строки и 81 920 байт в каждом повторе. Команды приведены в [инструкции](../technical-checks.md#7-проверка-метрик).

Стенд проверки метрик — Linux/WSL2 x86-64, 16 CPU и около 30,17 ГиБ памяти; запрос ограничен двумя потоками и 3 ГиБ. [Ресурсы](../../artifacts/checkpoint-1/metrics/load-check.json), [настройки прогона](../../artifacts/checkpoint-1/metrics/run.json). Результаты разных стендов обрабатываются отдельно.
