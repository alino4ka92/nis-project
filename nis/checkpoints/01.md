## Технические проверки

### Подготовка и проверка стенда

На ARM64 запущен образ `clickhouse/clickhouse-server:26.9.27.3`. Проверено подключение клиента: версия сервера совпала с выбранной, а запрос `SELECT 1` вернул `1`, как и ожидалось. [Запросы и полученные ответы](../../artifacts/checkpoint-1/docker-image-smoke.md) сохранены. Команды находятся в [инструкции запуска](../technical-checks.md#2-запуск-clickhouse).

Для коммита [`2da63c1b42ca`](https://github.com/ClickHouse/ClickHouse/commit/2da63c1b42ca1b31e42fae8837c6508a0eb07cff), указанного в карточке, доступна CI-сборка `26.9.1.552`, но официальный Docker-тег этой версии не опубликован. Для её запуска пришлось бы подготовить собственный образ из CI-бинарника. Поэтому для общего стенда выбран готовый официальный релиз `26.9.27.3`, опубликованный для ARM64 и x86-64. Это позволяет запускать сервер на разных компьютерах стандартными Docker-командами. Материалы ClickBench использованы с закреплённой ревизии.

Для эксперимента подготовлены схема таблицы и запросы ClickBench с ревизии `fa52f8524ad9`. Файлы совпадают с оригиналами; их происхождение и результаты проверки сохранены в [материалах ClickBench](../../third_party/clickbench/ORIGIN.md) и [source-materials.json](../../artifacts/checkpoint-1/source-materials.json).

### Данные и проверочный пример

Из всех 100 исходных Parquet-файлов ClickBench подготовлен датасет с отбором по условию `xxHash64(toString(toUInt64(WatchID))) % 100 = 0`. Выбранные строки объединены в общий Parquet с сохранением всех колонок. Этот датасет используется для проверки стенда, обоих физических вариантов таблицы и дальнейших запусков бенчмарка.

Отбор по хешу `WatchID` даёт воспроизводимую псевдослучайную выборку отдельных событий: при тех же исходных данных выбираются те же события независимо от порядка строк. Ожидается, что доли значений в колонках останутся близки к долям в полном исходном наборе, то есть распределения данных сохранятся приблизительно. Возможны статистические отклонения.

Функция `xxHash64` доступна и в Python, и в ClickHouse, поэтому правило можно проверить при подготовке и после загрузки.

Источники, правило отбора и контрольные суммы записаны в [манифесте](../../artifacts/checkpoint-1/clickbench-sample.json). Данные загружены в `nis_smoke.hits` по [исходной схеме ClickBench](../../third_party/clickbench/clickhouse/create.sql).

Для проверки загрузки ответ SQL-запроса в ClickHouse сопоставлен с независимым расчётом по Parquet-файлу в Python. Проверены количество отфильтрованных строк и сумма значений одной колонки; ответы совпали. Совпали также общее число строк и количество разных счётчиков и пользователей; все строки соответствуют правилу отбора по хешу. Точные значения приведены в [ожидаемом ответе](../../artifacts/checkpoint-1/clickbench-reference.json) и [результатах проверки](../../artifacts/checkpoint-1/clickbench-check.json). Команды находятся в [инструкции подготовки и загрузки](../technical-checks.md#4-подготовка-уменьшенного-clickbench).

### Пробный запуск ClickBench в Docker

Docker выбран для общего Linux-окружения на компьютерах участников: [авторский сценарий ClickBench](../../third_party/clickbench/README.md) рассчитан на Linux, а подготовка стенда выполнялась на macOS. Контейнер позволяет использовать одну версию клиента и один скрипт запуска на разных ОС.

Образ `nis-clickbench-benchmark` собран по [Dockerfile](../../docker/checkpoint-1/benchmark.Dockerfile) на основе официального `clickhouse/clickhouse-server:26.9.27.3`, из которого используется клиент ClickHouse. В образ добавлены [исходные SQL-запросы ClickBench](../../third_party/clickbench/clickhouse/queries.sql), [подготовленный для нашего стенда скрипт запуска](../../scripts/checkpoint-1/run_benchmark.sh) и [SQL для сбора метрик](../../sql/checkpoint-1-benchmark-metrics.sql). При старте контейнера скрипт подключается к уже работающему серверу ClickHouse, выполняет запросы с прогревом и повторами, сохраняет ответы и измерения в отдельный Docker volume. Таблица с данными хранится в контейнере сервера и его volume.

На загруженной выборке успешно выполнены все 43 исходных запроса ClickBench: для каждого проведены один прогрев и три измеряемых повтора. Сохранены ответы запросов и 129 измерений времени, прочитанных строк и байтов, CPU и памяти из `system.query_log`. В журнале подтверждены все прогревы и повторы; ошибок выполнения нет.

Ожидалось успешное выполнение запросов и получение всех пяти метрик; это подтверждено [результатами прогона](../../artifacts/checkpoint-1/benchmark/README.md). Команды сборки и повторного запуска находятся в [инструкции Docker](../../docker/checkpoint-1/README.md#пробный-запуск-clickbench). Прогон проверяет работу нагрузки и сбор измерений на выбранном датасете. На этом же наборе будет выполнено сравнение физических вариантов.

## Ресурсы

Тестовому стенду в Docker доступны 4 vCPU и около 8 ГиБ оперативной памяти. Подготовка и загрузка датасета уложились в выделенные ресурсы. Проверены расход памяти, размер таблицы и свободное место на диске с учётом двух физических вариантов и временных файлов. Измерения сохранены в [результате проверки](../../artifacts/checkpoint-1/clickbench-check.json), сведения о подготовке — в [манифесте](../../artifacts/checkpoint-1/clickbench-sample.json).

## Ответственность участников

### Участник 1

Подготовлены окружение, общий датасет с отбором по хешу из всех исходных файлов и Docker-образ запуска ClickBench. На подготовленном наборе проверены загрузка, выполнение запросов, сбор метрик и достаточность ресурсов.

### Участник 2

Будут подготовлены постановка исследования и план эксперимента: сравниваемые варианты, запросы, настройки и порядок запусков на подготовленном наборе данных.

### Участник 3

Будут описаны метрики, проверка правильности результатов и обработка измерений, собраны материалы контрольной точки. Для этого доступны сохранённые измерения пробного прогона.
